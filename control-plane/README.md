# VSVD Control Plane

Рабочий сервер для функций **VSVD**, а не прокси Telegram. Он выдаёт клиенту только активные кастомные бейджи по Telegram User ID и даёт администратору сайт для их создания, выдачи и отзыва.

## Что хранится

- шаблоны бейджей: название, цвета, области отображения;
- выдачи: Telegram User ID, шаблон, срок, причина, кто выдал/отозвал;
- учётные записи администраторов и журнал действий.

Не хранятся: Telegram-сообщения, медиа, номера телефонов, коды входа, auth keys, контакты или сессии.

## Локальный запуск

Требуется Node.js 20+; внешних npm-пакетов нет.

```bash
cd control-plane
npm run dev
```

В development-режиме открой `http://localhost:8787`, задай первый логин и пароль длиной не менее 12 символов. Данные появятся в `control-plane/data/store.json`; каталог игнорируется Git.

## API

- `GET /api/v1/health` — health-check;
- `GET /api/v1/badges/users/{telegramUserId}` — публичный активный snapshot бейджей для клиента;
- `/api/admin/*` — сессионная админка: bootstrap/login, шаблоны, выдачи, отзыв, аудит.

Админ-операции используют HttpOnly session cookie, SameSite=Strict, CSRF token, scrypt-хэш пароля, ограничение попыток входа и атомарную запись состояния. User ID принимает только положительное знаковое 64-битное число.

## Production

JSON-хранилище предназначено для разработки или маленького закрытого теста. Перед публичным запуском нужно:

1. Перенести данные в PostgreSQL и объектное хранилище для пакетов плагинов.
2. Использовать HTTPS на отдельном домене и оставить `VSVD_COOKIE_SECURE=1`.
3. Задать случайный `VSVD_BOOTSTRAP_TOKEN`; не включать `VSVD_ALLOW_INSECURE_FIRST_ADMIN`.
4. Ограничить доступ к админке VPN/SSO, включить passkey/TOTP, резервные копии и мониторинг.
5. Добавить Ed25519 подписи ответов о бейджах и локальную проверку подписи в релизном Android-клиенте.

Шаблон окружения: `.env.example`.
