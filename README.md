# VSVD — приватный Telegram-клиент для Android

Рабочее имя проекта — **VSVD**. Это собственный Android-клиент с интерфейсом на Kotlin/Jetpack Compose, будущей локальной интеграцией Telegram через TDLib, кастомными бейджами и безопасной системой плагинов.

> Текущий коммит — старт первого этапа: запускаемый UI-каркас, доменные контракты и архитектура. Это **не** готовый Telegram-клиент: экран чатов показывает явно помеченные демонстрационные данные, пока нативный TDLib не добавлен.

## Что уже заложено

- нативное Android-приложение на Kotlin, Compose и Material 3;
- разделение UI и Telegram-транспорта через `TelegramGateway`;
- приватный принцип: будущий TDLib работает прямо на телефоне, а не через сервер VSVD;
- представление бейджей в профиле и списках чатов только внутри VSVD;
- контракт, политика разрешений и интерфейс менеджера плагинов;
- UI менеджера плагинов без загрузки APK/DEX и произвольного кода.

## Как запустить каркас

Нужны Android Studio, Android SDK Platform 35 и JDK 17.

```bash
./gradlew :app:assembleDebug
```

После сборки APK находится в `app/build/outputs/apk/debug/`. На машине разработки можно также открыть корень проекта в Android Studio и нажать **Run**.

## Важные границы проекта

1. Содержимое чатов, медиа, номера телефонов, коды входа и ключи Telegram **не должны проходить через сервер VSVD**. Их источник — Telegram через TDLib на телефоне пользователя.
2. Для рабочего Telegram-входа владелец приложения создаёт собственное API-приложение на `my.telegram.org`. Его `api_id` и `api_hash` не коммитятся и не подменяются чужими ключами. Подробности: [docs/TDLIB_INTEGRATION.md](docs/TDLIB_INTEGRATION.md).
3. Бейджи — визуальная функция VSVD. Официальный Telegram и другие клиенты их не увидят.
4. Плагины будут ограниченными и подписанными пакетами данных. Установка чужих APK/Dex-файлов под видом плагина не допускается. См. [docs/PLUGIN_SYSTEM.md](docs/PLUGIN_SYSTEM.md).

## План разработки

1. **Telegram-клиент (текущий приоритет):** подключить TDLib, авторизацию, список чатов, историю, отправку сообщений, медиа и настройки.
2. **VSVD Control Plane:** отдельный API, каталог подписанных плагинов, серверная выдача и отзыв бейджей.
3. **Админка:** роли, шаблоны бейджей, журнал действий, публикация плагинов и управление ключами издателей.

Схема второго и третьего этапа находится в [docs/CONTROL_PLANE.md](docs/CONTROL_PLANE.md).
