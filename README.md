# VSVD for Android

**VSVD** — собственный Android-клиент, основанный на исходном коде официального Telegram for Android. Мы используем зрелый Telegram-транспорт и интерфейс как базу, а добавляем только функции VSVD: собственный бренд, кастомные бейджи, безопасные плагины и позднее — Control Plane с админкой.

> VSVD — неофициальный клиент, не связанный с Telegram. Не используем название Telegram или его логотип как бренд приложения.

## Состав репозитория

- `upstream/telegram-android` — закреплённый Git submodule официального Telegram Android на ревизии `dc780e8`;
- `patches/telegram-android/` — короткий, проверяемый набор изменений VSVD поверх этой ревизии;
- `scripts/apply-vsvd-patches.sh` — безопасно накладывает патчи только на ожидаемый upstream;
- `docs/` — спецификация плагинов, будущего Control Plane и инструкции сборки.

Такой формат не копирует тысячи файлов и тяжёлые нативные зависимости в наш патч, но остаётся настоящим форком исходников Telegram. Сам upstream тоже использует вложенные submodule для TDLib и нативных библиотек.

## Уже добавлено в патч VSVD

- бренд **VSVD**, отдельный package ID `dev.vsvd.client` и собственная иконка;
- использование только отдельного Telegram API ID приложения VSVD — официальные ключи, store URL, SafetyNet и passkeys не наследуются;
- локальная модель и хранилище кастомных бейджей;
- отображение бейджа рядом с пользователем в `UserCell` реального интерфейса Telegram;
- пункт **VSVD Client Settings** в настоящих настройках клиента: показ бейджей, URL сервера, синхронизация, User ID и настройка декларативных плагинов;
- отдельный `control-plane/` с админ-сайтом, каталогом бейджей, выдачей/отзывом по Telegram User ID и публичным endpoint для клиента;
- политика самодельных плагинов: только подписанные декларативные пакеты, без APK/DEX/нативного кода/скриптов;
- отключён повторно используемый SMS Retriever hash официального приложения.

VSVD Control Plane уже отдаёт активные бейджи по User ID, а клиент умеет запрашивать и кэшировать этот snapshot только после явного включения и настройки HTTPS URL в **VSVD Client Settings**. Telegram-переписка через него не проходит. Для публичного релиза необходимо добавить Ed25519-подпись серверных ответов и её проверку в Android-клиенте.

## Подготовка и сборка

Нужны Android Studio **2025.1.4**, Android SDK **36**, NDK **27.2.12479018**, JDK, Git и место для нативных зависимостей. Это требования текущей версии upstream.

```bash
# При первом клонировании
 git submodule update --init --recursive

# Наложить только наши изменения на официальный код
 ./scripts/apply-vsvd-patches.sh

# Собрать debug APK из исходников Telegram Android
 cd upstream/telegram-android
 ./gradlew :TMessagesProj_App:assembleAfatDebug
```

Перед входом создай своё приложение на `https://my.telegram.org`, затем скопируй `telegram.properties.example` в `telegram.properties` в **корне VSVD** и заполни значения. Этот файл игнорируется Git; не добавляй ключи в код, issue, логи или CI-артефакты.

```properties
TELEGRAM_API_ID=
TELEGRAM_API_HASH=
```

Точная инструкция, включая обязательный отдельный ключ для release APK: [docs/FORK_BUILD.md](docs/FORK_BUILD.md).

## Приватность и будущий сервер

Обычные Telegram-данные — чаты, сообщения, медиа, контакты, номер и коды входа — идут между устройством и Telegram через код клиента. Сервер VSVD не должен их принимать или проксировать. Он нужен только для подписанного каталога плагинов, бейджей, ролей и журнала действий админов.

Подробности: [docs/CONTROL_PLANE.md](docs/CONTROL_PLANE.md) и [docs/PLUGIN_SYSTEM.md](docs/PLUGIN_SYSTEM.md).

## Лицензия и обязательства форка

Telegram for Android распространяется под **GNU GPL v2 or later**. Поэтому при распространении VSVD APK исходный код VSVD вместе с применяемыми патчами, GPL-лицензией и информацией об upstream должен быть доступен пользователям. Нельзя выдавать VSVD за официальный Telegram-клиент, использовать официальный логотип или чужие API credentials.
