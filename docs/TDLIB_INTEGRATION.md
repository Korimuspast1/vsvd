# Интеграция TDLib

## Почему TDLib

TDLib берёт на себя протокол Telegram, локальную базу, синхронизацию и доставку обновлений. В VSVD он должен работать **внутри Android-приложения**. Это значит, что обычные Telegram-данные поступают по пути:

```text
Телефон с VSVD  <── зашифрованное соединение ──>  Telegram
```

Control Plane VSVD в этот маршрут не входит.

## Ключи приложения

1. Владелец VSVD регистрирует своё API-приложение на `https://my.telegram.org`.
2. Создаёт локальный файл `telegram.properties` по примеру `telegram.properties.example`.
3. На этапе добавления TDLib Gradle будет считывать значения только в локальную конфигурацию сборки. В Git, логи CI и ответы API эти значения не попадают.
4. Никогда не используем ключи официального Telegram-клиента или ключи другого разработчика.

`api_hash` нельзя считать полноценной защитой в APK; ограничение доступа, прозрачная политика и отдельный API ID приложения остаются обязательными.

## План реализации адаптера

`TelegramGateway` — единственная точка, через которую UI получает состояние сессии и данные. `PreviewTelegramGateway` сохранён только для запуска текущего UI без нативной библиотеки. Его необходимо заменить на `TdlibTelegramGateway`.

1. Добавить проверенный Android-артефакт TDLib в отдельный инфраструктурный модуль, закрепить версию и checksum в документации сборки.
2. На `AuthorizationStateWaitTdlibParameters` передать локальные каталоги БД, `api_id`, `api_hash`, модель устройства, версию Android и версию VSVD.
3. Обработать состояния: ключ шифрования БД, номер телефона, код, пароль двухэтапной проверки, готовая сессия, закрытие.
4. Преобразовывать объекты TDLib в небольшие доменные модели VSVD. В UI и плагин-рантайм не передавать исходные TDLib-объекты.
5. Реализовать список чатов, историю, отправку текста/медиа, индикаторы печати, уведомления и файловый кэш поэтапно.
6. Сессии и база TDLib остаются в sandbox приложения. При logout вызывается TDLib logout/close и очищаются локальные данные согласно выбору пользователя.

## Что не делает сервер VSVD

- не получает номер телефона, код Telegram, двухфакторный пароль или auth key;
- не проксирует MTProto/TDLib;
- не хранит содержимое личных сообщений, медиа, списки чатов или контакты;
- не используется для обхода ограничений Telegram.

## Перед включением тестового входа

Проверить на отдельном тестовом аккаунте:

- авторизацию с двухэтапной проверкой;
- logout и удаление локальных данных;
- работу после перезапуска и offline-режим;
- отсутствие номеров, кодов и текстов сообщений в Android Logcat, crash-reporting и сетевых логах;
- корректную обработку flood wait и ошибок сети без бесконечных ретраев.
