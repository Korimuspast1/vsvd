# Система плагинов VSVD

## Цель

Плагины добавляют **ограниченные** возможности интерфейса: темы, локальное оформление сообщений, кнопки-действия и локальные автоматизации. Они не являются мини-APK и не получают неограниченное выполнение кода.

Такой выбор нужен, чтобы расширение не могло украсть Telegram-сессию, читать локальную БД TDLib, показывать фишинговый экран входа или незаметно пересылать переписку.

## Формат пакета `.vsvd-plugin`

Это ZIP-файл с фиксированным составом:

```text
manifest.json       # ID, версия, возможности, hashes ресурсов
signature.ed25519   # подпись канонического manifest.json + hashes
assets/             # статические темы, иконки, локали
rules/              # декларативные правила разрешённого DSL
```

В пакете **запрещены**: APK, DEX, `.so`, исполняемые shell-файлы, WebView с удалённым JavaScript и скрытые архивы.

## Обязательные поля manifest

```json
{
  "id": "vsvd.appearance.night-aurora",
  "name": "Night Aurora",
  "version": "1.0.0",
  "minClientVersion": 1,
  "capabilities": ["THEME"],
  "publisherKeyId": "publisher-example-2026-01",
  "signatureAlgorithm": "Ed25519"
}
```

`id` уникален и состоит из строчных букв, цифр, точек и дефисов. Новая версия не может менять ID другого издателя.

## Разрешения

| Возможность | Что разрешено | Что запрещено |
| --- | --- | --- |
| `THEME` | цвета, типографика, статические ассеты | доступ к сообщениям |
| `MESSAGE_DECORATION` | локальное отображение уже отфильтрованных данных | изменение/отправка сообщения |
| `CHAT_ACTION` | показать явную команду пользователю | автоматическая отправка |
| `LOCAL_AUTOMATION` | действие после явного согласия пользователя | фоновая работа без индикации |
| `NETWORK_REQUEST` | запрос только к явно указанным HTTPS-доменам после согласия | Telegram-сессия, произвольные сокеты |

Ни один плагин не получает доступ к `TelegramGateway`, хранилищу TDLib, файлам приложения, номеру телефона, коду входа или токенам Control Plane.

## Проверка перед установкой

Клиент выполняет следующие проверки до распаковки в рабочую область:

1. Ограничение размера, числа файлов, пути без `../` и отсутствие запрещённых типов.
2. Канонизация manifest и сверка SHA-256 каждого ресурса.
3. Проверка Ed25519 подписи доверенным публичным ключом издателя.
4. Проверка версии VSVD и допустимых capabilities.
5. Явное подтверждение пользователя при первом включении нового разрешения.

Подписи и список отозванных ключей получаются из Control Plane, но проверяются локально. Если сервер недоступен, уже проверенный плагин продолжает работать в рамках ранее одобренных прав.

## Первый runtime

Первой реализацией будет маленький декларативный DSL: шаблоны темы, правила видимости кнопок и фиксированные действия. Поддержка JavaScript, Lua, Kotlin script, WebAssembly и загружаемого байткода в первый релиз не входит. Если выполнение кода вообще потребуется, оно будет рассматриваться отдельно: с sandbox-процессом, строгим IPC, лимитами CPU/памяти/сети и независимым аудитом.
